# Аналіз відгуків — клієнт-серверний вебзастосунок у хмарі

Індивідуальні завдання 1 і 2 з дисципліни «Інформаційні технології хмарних обчислень».
Лянскорунський К.О., група КН-23-1.

Вебзастосунок приймає відгуки користувачів про товари, зберігає їх у віддаленій
базі даних PostgreSQL і визначає тональність кожного відгуку модулем штучного
інтелекту.

| Завдання | Що реалізовано |
|---|---|
| ІЗ1 | Flask-застосунок, обробка запитів, віддалена БД PostgreSQL, CRUD відгуків |
| ІЗ2 | Модуль ШІ (Hugging Face API + власна модель), візуалізація, GitHub, CI/CD |

## Можливості

- додавання відгуку з валідацією полів на сервері;
- перегляд і фільтрація відгуків за категорією та тональністю;
- визначення тональності тексту модулем ШІ;
- сторінка аналітики: зведені показники, розподіл тональності, розріз за категоріями;
- JSON API: `POST /api/analyse`, `GET /api/stats`, `GET /health`.

## Архітектура

```
Браузер  ──HTTP──>  Flask (gunicorn)  ──SQL/TCP 5432──>  PostgreSQL (хмара)
                          │
                          └──HTTPS──>  Hugging Face Inference API
                                       (резерв: власна модель у app/model/)
```

### Структура бази даних

| Таблиця | Призначення |
|---|---|
| `users` | автори відгуків (унікальні за email) |
| `categories` | довідник категорій товарів |
| `reviews` | відгуки: текст, оцінка 1–5, автор, категорія |
| `analyses` | результат роботи модуля ШІ: тональність, впевненість, назва моделі |

Повна схема з обмеженнями цілісності — `migrations/schema.sql`.

### Модуль штучного інтелекту

Основний канал — хмарний сервіс **Hugging Face Inference API**
(`distilbert-base-uncased-finetuned-sst-2-english`). Якщо токен не заданий або
сервіс недоступний, застосунок автоматично переходить на **власну модель**
(TF-IDF + логістична регресія, навчена на IMDB Dataset of 50K Movie Reviews,
точність 0,9029), збережену у `app/model/sentiment_tfidf.joblib`.

## Запуск локально

```bash
pip install -r requirements.txt
cp .env.example .env          # вказати DATABASE_URL
python -c "from app.db import init_schema; init_schema()"
python scripts/seed.py        # необов'язково: демодані
python wsgi.py
```

Застосунок буде доступний за адресою http://127.0.0.1:5000

### Змінні середовища

| Змінна | Призначення |
|---|---|
| `DATABASE_URL` | рядок підключення до PostgreSQL (обов'язково) |
| `SECRET_KEY` | ключ сесій Flask |
| `HF_API_TOKEN` | токен Hugging Face; без нього працює власна модель |
| `HF_MODEL` | назва моделі Hugging Face |

## Тести та CI/CD

```bash
pytest tests/ -v
flake8 app tests scripts --max-line-length=100 --extend-ignore=E402
```

Конвеєр `.github/workflows/ci-cd.yml` на кожен push і pull request піднімає
PostgreSQL, застосовує схему, виконує перевірку стилю й тести та перевіряє, що
застосунок стартує під gunicorn. Після успішних тестів у гілці `main`
запускається розгортання у хмарі через deploy hook (секрет `RENDER_DEPLOY_HOOK`).

## Розгортання у хмарі

Конфігурація — `render.yaml`. Команда запуску: `gunicorn wsgi:app`.
Змінні середовища задаються в налаштуваннях сервісу; схема бази даних
застосовується автоматично під час першого запуску.
